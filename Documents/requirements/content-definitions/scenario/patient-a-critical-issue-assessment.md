# 환자 A 시나리오 점검 이슈 판정 및 문제 설명

## 1. 결론

전달받은 목록은 단순한 기획 변경 목록이 아니라, **시나리오 그래프에 정의된 의도와 실제 플레이 가능한 상호작용 사이의 불일치**를 기록한 QA 보고서다. 저장소 확인 결과 일부 항목은 이미 JSON/설계문서에 반영되었지만, 다수는 `Validator`와 신호 이름만 배선되어 있고 실제 씬의 producer, collider, 메뉴, 입력 처리, 이벤트 표시까지 end-to-end로 검증되지 않았다.

따라서 “신호가 JSON에 존재한다”는 이유만으로 문제가 없다고 판단할 수 없다. 최종 판정은 다음 네 조건을 모두 만족해야 한다.

1. 해당 노드 시점에 필요한 물품·메뉴·상호작용 지점만 보인다.
2. 안내문이 실제 사용 순서와 일치한다.
3. 사용자가 조작할 수 있고, 완료 콜백이 발생한다.
4. 콜백의 신호가 현재 Validator와 일치하며 다음 노드로 한 번만 진행된다.

## 2. 원래 기획과 의도

`patient_a_critical`은 `SPAWN_A`에서 환자 A와 필요한 초기 환경을 생성한 뒤, 이벤트 노드가 진행될 때마다 관련 장비를 노출하고, 플레이어가 의료 처치를 올바른 순서로 수행하면 `sig.*` 신호가 Validator를 통과시키는 구조다. 즉 모든 의료 장비를 시작부터 보여주는 방식이 아니라 **시나리오 단계별 progressive disclosure**가 의도다.

V015~V017은 기도 확보·산소 연결·지혈·정맥로 확보를 실제 조작 순서로 훈련시키는 구간이다. V019~V020은 Rapid Infuser와 혈액/수액 라인 연결, V022~V026은 앰부배깅·CPR·제세동 카트 이동·에피네프린 투여를 검증한다. `V` 노드는 판정 게이트이고, `E`는 처치 후 표현/이벤트, `N`은 안내, `D`는 대화, `C`는 선택/퀴즈다. 그러므로 게이트가 존재해도 그 게이트를 통과시킬 실제 producer가 없으면 시나리오는 진행 불가능하다.

## 3. 항목별 판정

판정 용어: **실재**는 현재 플레이를 막는 실제 결함, **부분 실재**는 설계/배선은 있으나 플레이 검증 또는 콘텐츠 연결이 부족한 상태, **기획 확인**은 구현 결함으로 단정하기 전에 원래 UX를 확정해야 하는 항목이다.

## 4. 종합 판단

목록의 핵심 원인은 세 가지다.

1. **그래프-씬 불일치**: Validator와 신호는 JSON에 있으나 실제 prefab의 collider, connection point, interactable, 이벤트 handler가 없다.
2. **입력 모델 불일치**: 기존 구현은 우클릭 선택/놓기 또는 F키 상호작용 중심인데, 의료 처치의 의도는 대상 조준 후 좌클릭으로 연결·적용·완료하는 흐름이다.
3. **콘텐츠-상태 표시 불일치**: 체크리스트·문제지·아이템·메뉴가 현재 단계의 상태와 동기화되지 않아, 기능이 있어도 사용자는 다음 행동을 알 수 없거나 이미 완료된 행동을 다시 보게 된다.

## 5. 해결 우선순위와 검증 방법

먼저 공통 상호작용 계층을 고쳐야 한다. 대상 hit-test, 메뉴 좌표 선택, 좌클릭 적용/연결, 단계별 active interaction을 정리한 뒤 각 신호를 검증해야 한다. 그 다음 V015~V017의 산소·IV 연결, t03의 item apply, V019~V020의 Rapid Infuser, V023~V026의 앰부백/카트/에피네프린 순으로 진행한다. UI 이벤트(E007/E023/E025/E027)와 문구는 해당 producer가 동작한 뒤 end-to-end로 확인한다.

각 Validator는 다음 테스트를 통과해야 한다.

- 필요한 오브젝트만 표시되고, 다음 단계의 오브젝트는 비활성이다.
- 안내문에 적힌 순서대로 한 명의 테스트 플레이어가 조작할 수 있다.
- 조작 1회당 의도한 `sig.*`가 정확히 1회 발생한다.
- 신호 발생 후 체크리스트/문제지가 즉시 갱신되고 다음 노드로 이동한다.
- 잘못된 대상·중복 collider·중복 메뉴가 신호를 발생시키지 않는다.
