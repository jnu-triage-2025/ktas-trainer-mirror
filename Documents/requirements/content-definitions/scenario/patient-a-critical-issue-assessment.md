# 환자 A 시나리오 점검 이슈 판정 및 문제 설명

## 1. 결론

전달받은 목록은 단순한 기획 변경 목록이 아니라, **시나리오 그래프에 정의된 의도와 실제 플레이 가능한 상호작용 사이의 불일치**를 기록한 QA 보고서다. 저장소 확인 결과 일부 항목은 이미 JSON/설계문서에 반영되었지만, 다수는 `Validator`와 신호 이름만 배선되어 있고 실제 씬의 producer, collider, 메뉴, 입력 처리, 이벤트 표시까지 end-to-end로 검증되지 않았다.

따라서 “신호가 JSON에 존재한다”는 이유만으로 문제가 없다고 판단할 수 없다. 최종 판정은 다음 네 조건을 모두 만족해야 한다.

1. 해당 노드 시점에 필요한 물품·메뉴·상호작용 지점만 보인다.
2. 안내문이 실제 사용 순서와 일치한다.
3. 사용자가 조작할 수 있고, 완료 콜백이 발생한다.
4. 콜백의 신호가 현재 Validator와 일치하며 다음 노드로 한 번만 진행된다.

## 2. 원래 기획과 의도

`patient_a_critical`은 `SPAWN_A`에서 환자 A와 필요한 초기 환경을 생성한 뒤, 이벤트 노드가 진행될 때마다 관련 장비를 노출하고, 플레이어가 의료 처치를 올바른 순서로 수행하면 `sig.*` 신호가 Validator를 통과시키는 구조다. 즉 모든 의료 장비를 시작부터 보여주는 방식이 아니라 **시나리오 단계별 progressive disclosure**가 의도다.

V015~V017은 기도 확보·산소 연결·지혈·정맥로 확보를 실제 조작 순서로 훈련시키는 구간이다. V019~V020은 Rapid Infuser와 혈액/수액 라인 연결, V022~V026은 앰부배깅·CPR·제세동 카트 이동·에피네프린 투여를 검증한다. `V` 노드는 판정 게이트이고, `E`는 처치 후 표현/이벤트, `N`은 안내, `D`는 대화, `C`는 선택/퀴즈다. 그러므로 게이트가 존재해도 그 게이트를 통과시킬 실제 producer가 없으면 시나리오는 진행 불가능하다.

## 3. 항목별 판정

판정 용어: **실재**는 현재 플레이를 막는 실제 결함, **부분 실재**는 설계/배선은 있으나 플레이 검증 또는 콘텐츠 연결이 부족한 상태, **기획 확인**은 구현 결함으로 단정하기 전에 원래 UX를 확정해야 하는 항목이다.

## 4. 종합 판단

목록의 핵심 원인은 세 가지다.

1. **그래프-씬 불일치**: Validator와 신호는 JSON에 있으나 실제 prefab의 collider, connection point, interactable, 이벤트 handler가 없다.
2. **입력 모델 불일치**: 기존 구현은 우클릭 선택/놓기 또는 F키 상호작용 중심인데, 의료 처치의 의도는 대상 조준 후 좌클릭으로 연결·적용·완료하는 흐름이다.
3. **콘텐츠-상태 표시 불일치**: 체크리스트·문제지·아이템·메뉴가 현재 단계의 상태와 동기화되지 않아, 기능이 있어도 사용자는 다음 행동을 알 수 없거나 이미 완료된 행동을 다시 보게 된다.

## 5. 2026-08-12 구현 결과

이번 작업에서는 현재 저장소에서 원인과 수정 범위를 확정할 수 있는 공통 계층 및 환자 A 전용 항목을 우선 해결했다.

### 해결됨

- 상호작용 메뉴의 행을 마우스로 클릭하면 중앙선에 있는 항목이 아니라 **클릭한 행**이 선택·실행되도록 수정했다.
- 선택형 문제에서 답을 제출한 직후 문제 패널과 입력 오버레이를 닫도록 수정했다. 다음 문제가 나타날 때까지 이전 문제지가 남는 현상을 제거했다.
- 환자 A 생성 시 후속 단계용 제세동 패드, 에피네프린 주사기, 생리식염수 주사기를 숨기고 해당 이벤트에서 필요한 표현만 활성화하도록 했다.
- Level 1 Rapid Infuser가 플라즈마 용액과 혈액 수혈 세트를 실제 상호작용 대상으로 받아들이고, 성공 시 각각 `sig.connect_ps1_to_lv1`, `sig.connect_blood_to_lv1`을 발생시키도록 했다.
- 환자 A의 맥박 확인 상호작용 신호를 Validator와 일치시켰다. 1차 소생 단계에는 r1만, ROSC 이후에는 r2만 활성화되도록 해 V022 미반응과 V024 중복 메뉴의 직접 원인을 제거했다.
- 조합된 에피네프린 및 생리식염수 주사기를 환자에게 좌클릭 적용하면 현재 소생 라운드에 맞는 `push_epi_r1/r2`, `push_ns_r1/r2` 신호가 발생하도록 했다.
- N011, N011_2, N011_3을 실제 조작 순서인 “18G 삽입 → 수액백 걸기 → 라인 연결” 흐름으로 고쳤고, D023 발화자를 의사 NPC로 변경했다.
- 우상단 퀘스트 문구를 단순 목표문에서 장갑·거즈·플라스터, IV, Rapid Infuser 등의 실제 수행 순서가 드러나는 문구로 보강했다.

### 부분 해결 또는 실플레이 확인 필요

- SPAWN_A의 확인된 단계 표현은 초기 비활성화했지만, 모든 환자 자식 오브젝트가 어떤 이벤트에 귀속되는지에 대한 완전한 콘텐츠 목록은 없다. 나머지 자식까지 일괄 숨기면 환자 본체나 초기 장비를 훼손할 수 있으므로 확인된 대상만 안전하게 처리했다.
- E007/E025 전용 체크리스트 UI 참조는 씬 정의에서 비어 있는 구간이 남아 있다. 퀘스트 문구는 보강했지만 실제 이벤트 패널의 표시 여부는 플레이 모드에서 확인해야 한다.
- V015 산소벽 장비, V016 장갑·거즈·플라스터, V017 캐뉼라·수액 라인, V023 앰부백 연결은 연결점·콜라이더·프리팹 배치가 여러 씬에 걸쳐 있어 현재 정적 정보만으로 안전하게 완성하지 않았다.
- C009는 단일 선택지를 유지할지 오답 선택지를 추가할지 교육 기획 결정이 필요하다.
- E027은 앰부배깅 애니메이터와 고정할 카메라 참조가 씬에 배선되어 있지 않다. 임의의 객체를 연결하면 다른 연출을 오작동시킬 수 있어 잔여 항목으로 남겼다.
- V025 카트는 신호뿐 아니라 실제 위치 이동 완료를 검증해야 한다. 네트워크 플레이에서의 소유권·이동 동기화 확인이 필요하다.

### 코드 리뷰 후 보정

- Rapid Infuser 상태 스냅샷에 수혈세트 상태가 누락되어 저장·복원 후 연결 상태가 사라지는 문제를 수정했다.
- `blood_bag`를 `blood_transfusion_set`으로 잘못 인정하던 범위를 제거했다.
- 혈액을 플라즈마보다 먼저 연결하면 sticky `V020` 신호가 미리 충족되는 문제를 막기 위해 플라즈마 연결 이후에만 수혈세트를 연결할 수 있게 했다. 클라이언트 UI뿐 아니라 서버 승인 경로에서도 같은 순서를 검증한다.
- 환자 A 전용 `push_epi_r1/r2`, `push_ns_r1/r2`가 다른 환자에게 주사기를 사용해도 발생할 수 있던 문제를 환자 식별자로 제한했다. 환자 B/C의 단계별 아이템 허용 검사도 우회하지 않도록 순서를 바로잡았다.
- 메뉴 클릭 이벤트 도중 UI 트리를 두 번 재생성하던 처리를 제거해 잘못된 행 실행과 UI Toolkit 이벤트 수명주기 오류 가능성을 줄였다.
- PatientMonitor의 `OnValidate`가 FishNet 기반 검증을 건너뛰던 회귀를 수정해 NetworkObject 자동 보정을 유지했다.
- 환자 IV 연결점과 상호작용 목록을 최초 접근 시에도 보장해 비활성/동적 스폰 객체의 Awake 순서에 따른 신호·메뉴 유실을 막았다.
- 연결 토폴로지의 에디터 모드 제거와 CareZone 장비 재설치 이벤트 순서를 바로잡아 같은 프레임의 해제·재연결 상태가 남지 않게 했다.
- 선택적 TTS 프로필은 null일 때 생략하되 의미 있는 명시적 null 링크는 보존하도록 직렬화 명세를 정리했다.
- 프로젝트 기본 그래픽 설정을 Low 프로필 정본(mip 2, LOD bias 0.75, maximum LOD 1)에 맞췄다.

### 자동 검증 결과

- 코드 리뷰 보정 후 환자 A 회귀 테스트 9개 통과: 초기 단계 표현 숨김, Rapid Infuser 허용·거부 품목과 연결 순서, 상태 저장, 정확한 완료 신호, 투약 환자·회차 범위를 검증했다.
- 시나리오·퀘스트 JSON 구문 검사 통과, 변경 파일 공백 오류 검사 통과.
- 2026-08-12 최종 전체 EditMode 테스트 186개 전부 통과했다. 시나리오 저장 왕복 27개, 그래픽 프리셋 15개, 환자 장비 연결 14개, Patient B/C 58개 및 월드 상호작용 신호 테스트를 포함한다.
- 전체 PlayMode 테스트 8개도 통과했다. 자동 테스트/CI의 PlayMode 진입을 막던 TTS bake 모달은 배치 모드에서 경고만 남기고 생략하도록 수정했다.
- 자동 검증은 깨끗하지만 아래 수동 체크리스트의 씬 참조·애니메이션·물리 연결·호스트/원격 실제 플레이 항목은 별도 완료 증거가 필요하다.

## 6. 해결 우선순위와 검증 방법

먼저 공통 상호작용 계층을 고쳐야 한다. 대상 hit-test, 메뉴 좌표 선택, 좌클릭 적용/연결, 단계별 active interaction을 정리한 뒤 각 신호를 검증해야 한다. 그 다음 V015~V017의 산소·IV 연결, t03의 item apply, V019~V020의 Rapid Infuser, V023~V026의 앰부백/카트/에피네프린 순으로 진행한다. UI 이벤트(E007/E023/E025/E027)와 문구는 해당 producer가 동작한 뒤 end-to-end로 확인한다.

각 Validator는 다음 테스트를 통과해야 한다.

- 필요한 오브젝트만 표시되고, 다음 단계의 오브젝트는 비활성이다.
- 안내문에 적힌 순서대로 한 명의 테스트 플레이어가 조작할 수 있다.
- 조작 1회당 의도한 `sig.*`가 정확히 1회 발생한다.
- 신호 발생 후 체크리스트/문제지가 즉시 갱신되고 다음 노드로 이동한다.
- 잘못된 대상·중복 collider·중복 메뉴가 신호를 발생시키지 않는다.

현재 저장소 문서상 SPAWN prefab 등록, P004 역할 정책, V017의 좌/우 순차 삽입 정책은 설계적으로 정리되어 있다. 그러나 관련 항목 다수의 상태가 “배선완료/실플레이 미검증”이므로, 이를 해결 완료로 보고하기보다는 **실플레이 검증 전의 부분 해결 상태**로 보고하는 것이 타당하다.
