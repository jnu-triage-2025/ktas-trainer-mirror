# 시나리오 인간 의사결정 콘텐츠 맥락

이 문서는 구현자가 임의로 결정해서는 안 되는 미결 사항을, 플레이어가 실제로 보는 안내·행동·
그 뒤의 전환 순서와 함께 설명한다. 이미 확정된 환자 A 의사 NPC 제출 상호작용 네 건은
[`patient_a_critical.md`](./patient_a_critical.md)의 「의사 NPC 제출 producer 콘텐츠 확정」을
정본으로 한다.

## 현재 결정이 필요한 항목

완료된 의사 NPC 제출 설정, 기본 조작 입력 판정, 택배 보관소 아이템 배치는 이 표에서 제외한다.

| 영역 | 결정할 내용 | 플레이어 영향 |
|---|---|---|
| 환자 A | `P004`의 2인 협업을 실제 다인 브랜치로 구현할지, 단일 담당으로 단순화/분리할지 | 삽관·산소 및 IV 보조에서 안내받은 역할과 실제 수행자가 일치한다. |
| 환자 A | 18G 캐뉼라 두 개의 준비 완료 기준 | 양측 정맥로 준비를 실제 두 개 획득으로 평가할지 결정한다. |
| 환자 A | `D037` 뒤 자동 다음 시나리오, 결과 화면, 독립 종료 중 어느 UX를 쓸지 | 흉부외과 이관 메시지 뒤의 화면 전환이 정해진다. |
| 환자 A | 활력 표시·스타일렛·T-piece·가슴압박·제세동 카트·의복 제거의 실제 클릭 영역과 완료 상태 | 각 안내가 실제 오브젝트와 정확히 연결되어 대기 상태에 빠지지 않는다. |
| 환자 B/C | Nurse A~D의 배타적 역할→tag 표 | 두 환자를 동시에 처치할 때 한 플레이어가 충돌 없이 자신의 작업을 수행한다. |
| 환자 B/C | 실제 환자 프리팹과 20G 삽입 팔 | 안내 문구, 보이는 캐뉼라, 판정 signal이 같은 팔을 가리킨다. |
| 환자 B/C | 환자 C를 B와 같은 좌측 상완 부상으로 통일하는 임상 승인 | C의 지혈·IV·시각물이 일관된 임상 상황을 보여 준다. |
| 튜토리얼 | 전용 scene/preset 및 `TUT_START`의 시작 시점 | 플레이어와 모자 NPC, 보관소, 택배가 준비된 뒤 튜토리얼이 시작된다. |
| 튜토리얼 | 모자 NPC 전 “F 키” Title의 UI/닫힘 정책 | 플레이어가 상호작용 안내를 자동으로 보거나 확인 후 진행한다. |
| 튜토리얼 | 감사 대사 뒤의 종료 UX | 로비 유지, 완료 화면, 다음 시나리오 전환 중 하나가 일관되게 적용된다. |

## 1. 환자 A: 협업을 실제 협업으로 보일지

### 플레이어 경험

의사가 삽관과 출혈·IV 처치를 지시한 뒤, 환자 A 시나리오는 세 작업을 병렬로 제시한다.
삽관/산소 공급은 간호사 A와 B, 출혈 조절은 간호사 C, 양측 IV 확보와 보조는 간호사 C와 D가
수행하는 서술이다. 삽관 흐름에서는 체크리스트로 후두경·기관내관·스타일렛·플라스터·5 cc
주사기를 준비한 후, 후두경과 기관내관, 주사기를 차례로 의사에게 전달한다. IV 흐름은 18G
캐뉼라와 두 종류의 수액을 준비하고 좌·우 팔에 정맥로를 확보하는 흐름이다.

### 현재 충돌과 결정

현재 `ByRole` 병렬 배정은 하나의 브랜치를 한 명에게만 배정한다. 따라서 화면과 대사는 “A와 B가
함께”라고 말하지만, 실제로는 한 명에게 두 역할 태그가 모두 있어야 하거나 한 명이 전체를 수행하게
된다. 아래 중 하나를 확정해야 한다.

1. 실제 2인 협업으로 유지: 서버 권위의 다중 참여자 브랜치와 합류 조건을 구현한다.
2. 단일 수행으로 단순화: 대사·퀘스트의 “간호사 A와 B”, “간호사 C와 D”를 한 명의 담당 역할로 고친다.
3. 작업을 별도 브랜치로 분리: 예를 들어 삽관 준비와 산소 공급을 독립적으로 완료한 뒤 합류시킨다.

선택하지 않으면 플레이어가 맡은 역할과 실제 수행 가능한 행동이 어긋난다.

## 2. 환자 A: 18G 두 개를 언제 준비 완료로 볼지

### 플레이어 경험

플레이어는 18G 캐뉼라, 생리식염수 1L, 플라즈마 솔루션 1L를 준비한다. 이후 좌측 팔에 18G를
삽입하고 생리식염수를 연결하며, 반대쪽 팔의 18G와 플라즈마 솔루션 연결은 자동 진행으로 안내된다.
현재 처치 결과는 좌측/우측 삽입 signal로 이미 구분된다.

### 현재 충돌과 결정

준비 체크리스트에는 18G 두 개가 필요하지만, 현재 획득 signal은 `click_18g` 하나라 한 개를
주웠는지 두 개를 주웠는지 구분할 수 없다. 다음 중 하나를 확정한다.

1. 캐뉼라 두 개를 각각 획득하게 하고 좌·우별 signal을 발신한다.
2. 인벤토리의 `18G` 보유 수량이 2인지 검사한다.
3. 두 번째 캐뉼라는 자동 준비로 간주하고, 플레이어에게 하나만 획득하게 한다. 이 경우 체크리스트와
   대사를 그 의도에 맞게 바꾼다.

이 결정은 학습자가 “양측 정맥로 확보”를 실제로 두 번 수행했다고 평가할지에 영향을 준다.

## 3. 환자 A 종료: 다음 장면의 의미

### 플레이어 경험

ROSC 뒤 의식 상태와 전신 노출을 마치면 시스템은 “시나리오 A 환자 대응 종료. 흉부외과로 환자를
이관하였습니다.”라고 알린다. 기획서에는 검은 화면 fade-out 뒤 다시 밝아지며 다음 시나리오로
이어진다고 적혀 있지만, 실제 그래프의 `D037`은 종료(`null`)다.

### 결정

다음 중 하나를 확정한다.

1. 환자 B/C(`patient_b_c_ct`)를 자동 시작한다. 전체 운영 문서의 `disaster_intro → 환자 A → 환자 B/C`
   순서와 가장 잘 맞는다.
2. 결과/디브리핑 화면으로 이동하고 플레이어가 다음 시나리오를 시작하게 한다.
3. 환자 A만 독립 종료한다. 이 경우 “다음 시나리오로 이어짐” 문구를 삭제한다.

fade-out의 지속시간과 입력 잠금 여부도 같은 UX 결정에 포함한다.

## 4. 환자 A: 남은 여섯 producer의 실제 상호작용 지점

아래는 새로운 의학적 분기를 고르는 일이 아니라, 플레이어가 무엇을 클릭하고 어느 순간 완료로
판정할지를 확정하는 콘텐츠 저작이다. 미배선이면 해당 Validator는 대기 상태에서 멈춘다.

| 신호 | 플레이어가 보는 지시 | 확정할 실제 콘텐츠 |
|---|---|---|
| `show_vital_patient_a` | 활력 측정 도구를 선택한 뒤 환자를 클릭하여 모니터에 활력 표시 | 환자 본체 클릭 시점, 모니터 UI가 열린 시점, 또는 수치 표시 완료 시점 중 완료 기준 |
| `remove_intu_stylet` | 구강에 삽입된 기관내관을 클릭해 스타일렛 제거 | 기관내관의 어느 child object가 상호작용 대상인지와 제거 후 시각 상태 |
| `remove_tpiece` | 환자에 연결된 T-piece를 클릭해 해제 | T-piece의 클릭 영역, 해제 뒤 산소 장비가 보이는 방식 |
| `click_to_start_comp` | 환자 가슴을 클릭해 가슴압박 시작 | 흉부 상호작용 영역과 반복 압박 애니메이션을 시작하는 최초 클릭의 기준 |
| `move_defibcart_to_patient` | 제세동 카트를 환자 옆으로 이동 | “환자 옆”의 위치/거리 판정과 카트가 놓일 자리 |
| `remove_patient_clothing` | 가위를 획득한 뒤 환자를 클릭해 의복 제거 | 클릭 부위, 의복 제거 전후 모델, 노출 사정이 시작되는 시점 |

## 5. 환자 B/C: 두 환자를 동시에 돌보는 역할 분담

### 플레이어 경험

환자 B와 C, 분류용 더미 B를 분류 구역으로 옮긴 뒤 환자 B 그룹과 C 그룹이 동시에 처치를 시작한다.
각 환자는 의식·활력·동공 사정, 산소 공급, 지혈, IV 확보를 거쳐 의사의 Brain CT 지시 후 CT실로
이동한다. 현재 태그에서는 `bleeding_control`이 B와 C에 모두 쓰이고, 초기 C 그룹 태그
(`airway_team`, `iv_team`)와 이후 C의 의식·활력·동공·지혈 태그가 다르다.

### 결정

간호사 A~D를 각 환자 그룹의 담당자로 고정할지, 단계마다 재배정할지를 먼저 정한다. 그 결과로
역할→tag 표와 배타 규칙을 확정해야 한다. 한 명이 B와 C의 같은 시점 브랜치에 동시에 배정될 수
없어야 한다. 그렇지 않으면 한 플레이어가 두 환자의 동시 처치를 떠맡거나, 반대로 필요한 브랜치가
담당자 없이 대기한다.

## 6. 환자 B/C: 어느 팔을 실제로 IV 처치할지

### 플레이어 경험

환자 B에게는 준비한 생리식염수 1L를 우측 팔의 20G 캐뉼라에 연결하라고 안내하고, 환자 C에게는
같은 행동을 좌측 팔에서 하라고 안내한다. 두 환자는 현재 정본 문서상 동일한 좌측 상완 개방성 골절과
두부 손상으로 설정되어 있다.

### 현재 충돌과 결정

기본 IV 구현은 좌측부터 처리하는데, B 프리팹의 20G 시각물도 좌측에만 남아 있다. B에게 우측을
누르게 하면 보이는 모델과 판정 signal이 다르고, 좌측으로 바꾸면 현재 안내 문구와 달라진다.

임상 담당자는 (a) B와 C의 실제 프리팹/성별, (b) 각 환자의 삽입 팔, (c) 골절 부위와 IV 가능 팔을
함께 확정해야 한다. 확정 후 상호작용 지점, 시각물, `insert_iv_patient_{b|c}_{left|right}` signal,
안내 문구를 모두 같은 팔로 맞춘다.

## 7. 환자 C 부상 통일안의 임상 승인

### 플레이어 경험

현재 목표 콘텐츠는 C를 B와 동일 부상으로 보여 준다. 즉 좌측 상완 개방성 골절과 두부 손상, GCS 13,
좌측 상완 지혈이다. 다만 동공 반응은 C 전용 흐름대로 좌측 무반응으로 유지한다. 과거 JSON은 C를
무릎 하단 출혈/한쪽 팔로 표시해, 플레이어가 문서와 다른 부위를 처치하는 문제가 있었다.

### 결정

“B와 동일 부상, 단 C의 좌측 동공 무반응은 유지”를 임상적으로 승인할지 확인한다. 승인 시 과거의
무릎 하단 출혈 표현과 관련 상호작용/시각물을 제거하고 JSON에 같은 내용을 반영한다. 다른 임상 시나리오를
의도했다면, C의 부상·활력·지혈 부위·동공·IV 팔을 한 세트로 새로 정의해야 한다.

## 8. 튜토리얼: 플레이어가 처음 배우는 규칙

### 시작과 이동 판정 (완료)

플레이어는 “WASD 키와 마우스를 사용하여 캐릭터를 이동하세요”라는 미니 퀘스트를 받고, 완료 0.5초 뒤
“저기요! 잠시만요!”라는 호출을 듣는다. 이 완료 규칙은 확정되었다. 전용
`BasicMovementControlTutorialQuestResolver`가 WASD, 마우스 버튼, 마우스 이동에 따른 카메라 회전 중
하나라도 발생한 프레임의 시간을 합산한다. 같은 프레임에 여러 입력을 하더라도 시간은 한 번만 더하며,
합계가 1초를 초과하면 `tutorial-move`를 완료하고 `tutorial_player_moved` signal을 발신한다.

### 이동 뒤 호출 대기 (완료)

이동 퀘스트가 끝나면 `DL_TUT_MOVE_CALL_DELAY` Delay node가 500 ms를 기다리고 호출 대사로
진행한다. 시간은 공통 `ScenarioTimeValue`의 `{ "value": 500, "unit": "Milliseconds" }`로
표현하므로 프레임이나 네트워크 tick rate에 따라 문서 의미가 바뀌지 않는다.

### 모자 NPC를 만나는 순간

호출 뒤 플레이어는 `npc-tutorial-guide-hat` 근처에서 F 키로 대화를 시작한다. 화면에는
“주변에 인물이 존재한다면, F 키를 눌러 말을 걸 수 있습니다.”라는 Title 안내가 필요하다.
이 안내를 잠시 보여 주고 자동으로 사라지게 할지, 확인 입력을 받아야 사라지게 할지 결정한다.
전자는 흐름을 빠르게 만들고, 후자는 상호작용 키를 놓치지 않게 한다.

### 택배 퀘스트와 오답 아이템 (완료)

모자는 로비의 택배를 가져와 달라고 요청한다. 플레이어는 `delivery-storage-spot`으로 이동하고,
아이템 앞에서 F 키로 `tutorial_delivery_package`를 획득한 뒤 모자에게 제출한다. 기획서에는 마우스 휠
상호작용을 익히도록 여러 물품을 흩뿌리고, 오답을 집으면 “이건 아닌 것 같다”는 독백을 한 번만 보이게
하자는 제안도 있다.

정답은 `택배: 모자님 앞`이며 중앙 선반에서 `tutorial_delivery_package`를 지급한다. 오답은
`배달: 밤샜음 청년`, `택배: 8909`, `우편: 김강산님` 세 개로 확정했다. 각 물품의 scene object
identifier·item definition identifier·선반 위치·1회성 독백은
[`tutorial.md`](./tutorial.md)의 「택배 보관소 아이템 배치 확정」을 정본으로 한다.

### 튜토리얼 종료

제출 뒤 모자는 “감사합니다! 덕분에 일이 잘 해결되었네요..!”라고 말한다. 이 뒤 로비에 남길지,
완료 화면을 보일지, 재난 시나리오로 전환할지 정해지지 않았다. 이 선택은 튜토리얼을 독립 체험으로
보는지 정규 교육 흐름의 첫 단계로 보는지를 결정한다.

## 결정이 아닌 운영/검수 항목

다음은 콘텐츠 선택이 아니라, 확정된 내용을 실제 씬에서 성립시키는 작업이다.

- 환자 A/B/C prefab을 네트워크 spawnable prefab으로 등록한다.
- B/C 환자와 더미의 identifier, 사정 action, 활력 UI, IV 연결점, waypoint를 요구된 signal과 일치시킨다.
- 환자 A 체온 35.9°C, KTAS 등급, 산소 10 L·에피네프린 1 mg·18G/20G 선택은 임상 검수로 승인한다.
- 환자 B/C 종료 fade와 환자 A 종료 fade는 선택된 종료 UX에 맞춰 handler와 전이를 배선한다.
