# Indev 씬 중복 실행 및 연결 종료 처리

## 목적

Indev 씬을 복제해 여러 클라이언트를 실행할 때 첫 번째 프로세스만 서버를 열고, 나머지 프로세스는 같은 포트의 기존 서버에 접속한다. 서버 종료나 접속 실패 시 사용자가 원인을 확인할 수 있는 전체 화면 상태를 제공한다.

## 동작 요구사항

1. `IndevSceneBootstrapper`는 세션 시작 전에 설정된 UDP 포트를 점검한다.
2. 포트가 비어 있으면 기존과 같이 서버와 로컬 클라이언트를 함께 시작한다.
3. 포트가 점유되어 있으면 서버를 시작하지 않고 클라이언트만 시작한다.
4. 점유 여부 확인에 실패한 경우에는 오류를 기록하고 서버 시작을 시도한다.
5. 연결된 뒤 서버가 종료되면 `서버가 종료되었습니다.`를 표시한다.
6. 최초 접속에 실패하거나 연결 시작 자체가 실패하면 오류 메시지와 `자세한 내용은 세션 로그를 참조하세요.`를 표시한다.
7. 연결 종료 사유와 엔드포인트는 `GameLogService`의 현재 세션 로그에 기록한다.

## Unity 설정

- `IndevSceneBootstrapper`가 있는 오브젝트에 `IndevConnectionFailureOverlay`를 별도로 추가할 필요는 없다. 부트스트래퍼가 런타임에 자동으로 추가한다.
- `address`, `port`, `sessionName`은 기존 부트스트래퍼 설정을 사용한다.
- 오류 화면은 `NetworkSessionFailureScene`의 `UIDocument`/UXML/USS로 제공된다.
- 각 네트워크 세션 부트스트래퍼가 시작 단계에서 이 씬을 애디티브로 미리 로드하고 루트를 숨겨 둔다. 장애 시에는 추가 로딩 없이 UI 루트만 즉시 표시한다.
- Indev, Tutorial, Ingame 세션 부트스트래퍼가 동일한 종료 씬과 컨트롤러를 공유한다.

## 검증 절차

1. Indev 씬을 한 번 실행해 포트가 비어 있는 상태에서 호스트가 시작되는지 확인한다.
2. 같은 프로젝트의 Indev 씬을 두 번째 플레이어로 복제 실행한다.
3. 두 번째 실행 로그에 `기존 서버에 클라이언트로 접속합니다.`가 기록되고 서버가 추가로 생성되지 않는지 확인한다.
4. 호스트를 종료한 뒤 두 번째 실행 화면에 서버 종료 메시지가 표시되는지 확인한다.
5. 잘못된 주소 또는 포트로 실행해 오류 메시지와 세션 로그 경로가 표시되는지 확인한다.
