## 동시 실행과 대화창 점유 충돌(Concurrency Conflict Policy)

`Dialogue`/`Choice`/`Quiz` 같은 대화창 계열 UI는 한 번에 하나만 표시될 수 있습니다. 그런데 두 개 이상의 시나리오 흐름(서로 다른 그래프, 또는 `Parallel`의 서로 다른 브랜치)이 동시에 대화창을 점유하려 하면 대사·선택지가 서로 덮어써지거나 뒤섞여 의도되지 않은 동작이 됩니다. 엔진은 이를 **대화창 점유 노드가 실제로 표시되는 시점**에 감지하고, 설정된 정책에 따라 처리합니다.

| 정책 | 의미 |
|---|---|
| `Warn`(기본값) | 경고(콘솔+인게임챗)를 남기고 그대로 진행합니다(undefined behavior 허용). 기존 동작과 동일합니다. |
| `Cancel` | 나중에 대화창을 점유하려 한 흐름/브랜치만 취소하고, 먼저 점유한 흐름은 보존합니다. |
| `Panic` | 진행 중인 모든 시나리오를 안전하게 중단(`EndScenario`)합니다. |

- 감지 기준: 대화창 노드 실행 시점에 "다른 그래프/흐름이 이미 대화창을 점유 중인가"를 검사합니다. 같은 그래프 내 `Parallel` 브랜치의 동시 프롬프트는 엔진이 이미 순서대로 직렬화하므로, 전역 경로에서만 "동시 프롬프트"도 충돌로 취급합니다.
- 단일 흐름으로만 구성된 대다수 시나리오는 점유자가 하나뿐이라 이 로직이 개입하지 않습니다(동작 불변).
- 기본값 `Warn`에서는 충돌 시에도 점유권을 넘겨받아 기존 덮어쓰기 동작을 유지하며 경고만 추가됩니다.

> **주의 — `Cancel`/`Panic` 과 `Parallel waitMode`**: 충돌로 인해 브랜치가 취소(`Cancel`)되면, 그 브랜치는 자신의 완료 조건(`completionConditionIdentifier`)에 도달하지 못한 채 종료됩니다. 상위 `Parallel` 노드가 `waitMode: All`이면 취소된 브랜치의 완료를 무한정 기다려 조인이 막힐 수 있습니다. `Panic`은 전체 시나리오를 중단하므로 이 문제는 없지만, 진행 중이던 다른 브랜치도 함께 종료됩니다. 대화창을 점유하는 브랜치가 여럿인 협동 시나리오에서 `Cancel`을 사용할 때는 `waitMode`를 `Any`/`None`으로 두거나, 애초에 대화창 점유가 겹치지 않도록 설계하는 것을 권장합니다.

### 인게임 커맨드

```
/scenario conflictpolicy               # 현재 정책 조회
/scenario conflictpolicy warn|cancel|panic   # 정책 변경(숫자 별칭 0/1/2 허용)
```

정책은 `ScenarioController.ConcurrencyConflictPolicy`(인스펙터의 "Concurrency (동시 실행 충돌)" 헤더)로도 설정할 수 있으며, 컴포넌트를 처음 붙일 때 기본값 `Warn`으로 초기화됩니다.
