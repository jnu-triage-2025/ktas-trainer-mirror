# AI 작업 흐름 가이드

## 1. 사전 준비

- 작업 목표를 한 문장으로 요약합니다.
- 관련 문서를 모두 열어 AI에게 제공할 준비를 합니다.
- 필요한 프롬프트(AI 지시문) 템플릿을 [Agents/Templates](../../Agents/Templates/)에서 찾아서 필요에 맞게 수정합니다.

## 2. AI에게 전달할 기본 정보

템플릿을 수정하여 무엇을 만들고 싶은지 최대한 구체적으로 설명합니다. 예제 중에는 기술적인 표현이 사용되는 경우가 있으나, 최대한 자세하게 설명만 한다면 기술적인 표현 사용 여부는 선택입니다.

## 3. AI에게 요청하는 방식

다음 항목을 포함하도록 요청합니다.

- 필요한 파일 목록과 경로 제안
- 구현 이전에 필요한 확인 질문
- 템플릿의 수정/삭제가 필요한 문구
- 산출물별 품질 검토 항목

## 4. 결과물 검토 체크

결과물이 잘 동작하는지 유니티에서 테스트합니다. 테스트는 IndevScene에서 수행합니다. 자세한 내용은 [온보딩 가이드의 &lt;작업 시 유니티 테스트&gt; 문단을 참고하세요.](../onboarding.md#작업-시-유니티-테스트)

- 파일 경로가 규칙을 따르는가
- 식별자/이벤트 이름이 일관적인가
- 문서 링크가 끊기지 않는가

<br />

- 유니티에서 오류가 나지는 않는가?
    유니티에서는 모든 C# 스크립트를 검토하므로, 사용하지 않는 스크립트라도 오류가 존재한다면 오류가 납니다.  
    ![alt text](../_static/ai-workflow__console-tab.png)  
    유니티 에디터의 Console 탭에서 Clear 버튼을 눌러도 사라지지 않는 오류가 있는지 확인합니다. 오류는 빨간색 느낌표 아이콘으로 표시됩니다: ![alt text](../_static/ai-workflow__error.png)  

- 오류가 난다면..
    1. AI가 생성하면서 함께 제공한 인간 작업자가 해야하는 작업이 있는지, 그 사항을 따랐는지 확인합니다. (이 사항을 이해하지 못했다면 AI에게 다시 물어봅니다.)
    2. 오류 메시지를 복사합니다.
    3. AI에게 오류 메시지와 함께 "이 오류를 수정해줘"라고 요청합니다.
    4. 수정된 파일을 유니티에 반영하고, 오류가 사라졌는지 확인합니다.
    5. 여전히 오류가 난다면 1~4단계를 반복합니다.

## 5. 커밋 전 제출 패키지

AI 결과물을 검토한 뒤, 아래 정보를 함께 정리합니다.

- 변경 요약 (1~2문장)
- 변경 파일 목록
- 새로운 식별자 목록 (이벤트/노드/프리팹)
- 추가로 확인이 필요한 사항

## 6. 구현체 문서화 적용 과정

모듈 구현체를 문서화할 때는 아래 순서를 따릅니다.

1. 구현체 인벤토리 수집
    - `Assets/Modules/MultiplayerInfrastructure/**/*.cs`, `Assets/Modules/TriageTrainer/**/*.cs` 목록을 먼저 수집합니다.
2. 기존 문서 커버리지 대조
    - `Documents/requirements/**`, `Documents/api-references/**`와 대조해 미문서 영역을 식별합니다.
3. 우선순위 확정
    - 런타임 핵심 경로(시나리오 실행, 상태/태그 동기화, 이벤트 부트스트랩, 핵심 UI/모니터)를 우선 문서화합니다.
4. 문서 작성
    - 요구사항 성격은 `requirements`에, API/메서드 성격은 `api-references`에 작성합니다.
5. workflow 반영
    - 이번처럼 문서화 방식을 반복해야 하는 경우, 본 문서에 절차를 추가해 팀 표준으로 고정합니다.
6. 링크/정합성 검증
    - 신규 문서를 README나 관련 문서에서 탐색 가능하게 연결하고, 경로 깨짐이 없는지 확인합니다.
