# 채팅 전송 결과 표시 제안

## 개요

일반 채팅을 전송한 사용자가 자신의 새 메시지를 수신 알림과 같은 토스트로 확인할 수 있도록 한다. 서버가 검증하고 모든 접속자에게 반향한 메시지는 기존 수신 경로로 로그와 토스트에 추가된다.

## 해결하려는 문제 상황

일반 채팅은 서버의 Observers RPC를 수신한 뒤에만 로그에 추가된다. 기존 구현은 `Enter` 처리에서 RPC 수신보다 먼저 패널을 닫고, 닫는 과정에서 UIDocument 전체를 숨긴다. 따라서 발신자를 포함한 수신자의 토스트가 생성되어도 화면에 표시되지 않는다.

## 사용자 경험 목표

- 일반 채팅과 명령어 모두 전송하면 입력란은 비워지고 채팅 패널은 닫힌다.
- 서버가 메시지를 반영하면 발신자와 다른 접속자 모두 최신 메시지를 토스트로 확인한다.
- 닫힌 채팅 UIDocument는 비상호작용 상태여서 게임 조작을 가로채지 않는다.
- `Esc`로 채팅 패널을 닫는 기존 동작은 유지한다.

## 제안

`ChatUIController.HandleSubmitKey()`의 기존 즉시 `Close()` 호출을 유지한다. `HidePanel()` 및 초기 숨김 처리에서는 UIDocument를 `display: none`으로 숨기지 않고, 표시 상태를 유지한 채 전체 트리의 입력 처리를 비활성화한다. 메시지 표시, 서버 검증, 쿨다운, 토스트는 기존 `ChatService` 및 `ChatPanelElement` 흐름을 변경하지 않는다.

## 자세한 달성 목표

1. `T`로 연 패널에서 일반 메시지를 입력하고 `Enter`를 누른다.
2. 입력란이 비워지고 패널이 닫힌다.
3. 서버 반향 메시지가 다른 수신 메시지와 동일한 토스트로 표시된다.
4. `/help` 같은 명령어도 제출한 뒤 패널이 닫힌다.
5. `Esc`는 일반 채팅과 명령어 입력 모두에서 패널을 닫는다.

## 문서화

- `miui_chat_panel` 요구사항에 일반 채팅과 명령어 제출 후의 패널 상태를 구분해 기록한다.
- 이 제안서와 예제 구현 문서로 시스템 모듈 변경의 목적과 검증 절차를 남긴다.

## 가용성과 테스트

- 서버 쿨다운 또는 검증 실패 시에도 시스템 오류 메시지를 토스트로 확인할 수 있다.
- Host와 원격 Client에서 일반 채팅, 명령어, `Esc` 닫힘을 각각 수동 Play Mode로 검증한다.
- 컴파일로 `ChatUIController` 변경이 기존 UI/입력 의존성과 호환되는지 검증한다.

## 구현에 성공한 구현체는 무엇이며, 성공 여부는 어떻게 측정할 수 있나요?

- 일반 채팅 전송 직후 패널이 닫힌다.
- 서버 반향 메시지가 발신자와 다른 수신자에게 한 번씩 토스트로 표시된다.
- 닫힌 채팅 UI가 키보드나 포인터 입력을 가로채지 않는다.
