# GitLab Work Items

Use the GitLab Work Items Tool at `Tools/gitlab-work-items/gitlab_work_items.py` with `GITLAB_TOKEN`. Before starting the tool, source the local profile appropriate for the current shell so the configured token is available to the child process. Never print the token or include it in logs. Call `gitlab_is_available` first. A non-empty, non-whitespace token means the tool is available; availability does not prove authorization. Use `gitlab_init` only to validate a supplied token profile—never print or persist the secret.

## Standard workflow

1. If a human names a specific issue, load it with `gitlab_get_work_item`, verify its project, title, description, and relevance to the current code before changing it.
2. If the request is underspecified, call `gitlab_work_item_index` for the relevant `project_path`. Follow `pageInfo.endCursor` until enough open items are indexed. Select only an item supported by the repository evidence; do not close unrelated work.
3. Inspect and test the code. Make the smallest safe fix, then update the Work Item with `gitlab_update_work_item` and add a concise evidence comment with `gitlab_comment_work_item`.
4. When a defect is found in already-committed code and no matching item exists, create one using the template at `SKILLS/gitlab-work-items/templates/bug.md`, then include reproduction evidence and the affected commit or file.
5. Never claim completion without reporting the Work Item IID/URL, changed files, validation performed, and any remaining risk.

Use GitLab global IDs (`gid://gitlab/...`) for Work Item and note mutations. Project and namespace lookup uses full paths. Keep list requests at 100 or fewer nodes and paginate. Queries need `read_api`; mutations need `api`. Treat GraphQL `errors` and mutation `errors` as failures and surface them.

## AI attribution

Whenever you add wholly new text to GitLab—opening a new issue or Work Item, adding a comment, or otherwise authoring fresh content rather than editing existing text—prepend `` `Generated by AI Agent`  <br /> `` to the very beginning of the body. This applies to `gitlab_create_work_item` descriptions and `gitlab_comment_work_item` bodies alike.

## Issue creation template

Read and fill `templates/bug.md`; do not replace reproducible evidence with a vague summary. Keep secrets, tokens, and private customer data out of issue bodies.
